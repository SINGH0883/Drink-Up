# Drink Up: Capacitor Android APK Plan

Repo: https://github.com/SINGH0883/Drink-Up

Goal: a simple, fast, good-looking Android app (.apk) built with Capacitor, with light and dark mode and strong UI/UX.

> Assumption: Drink Up is a water-reminder / hydration-tracker app. Adjust the screens if the idea is different.

---

## 1. Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | React + Vite + TypeScript | Fast builds; Capacitor wraps the `dist/` folder directly |
| Styling | Tailwind CSS + CSS variables | Easy, consistent light/dark theming |
| Native wrapper | Capacitor (latest) | Generates the Android project and APK |
| Storage | `@capacitor/preferences` (SQLite later if needed) | Offline, no backend |
| Reminders | `@capacitor/local-notifications` | Hydration reminders without a server |
| Native feel | `@capacitor/haptics`, `@capacitor/status-bar`, `@capacitor/splash-screen` | Feels like a real app, not a website |
| Charts | Plain SVG or a small chart library | Keeps the app light |

## 3. Build Steps

1. **Scaffold:** `npm create vite@latest . -- --template react-ts`, then install Tailwind CSS.
2. **Add Capacitor:**
   ```bash
   npm i @capacitor/core @capacitor/cli
   npx cap init "Drink Up" com.singh0883.drinkup --web-dir=dist
   ```
3. **Add Android:**
   ```bash
   npm i @capacitor/android
   npx cap add android
   ```
4. **Add plugins:**
   ```bash
   npm i @capacitor/preferences @capacitor/local-notifications @capacitor/haptics @capacitor/status-bar @capacitor/splash-screen
   ```
5. **Build the screens** (see section 4).
6. **Sync web build to Android:**
   ```bash
   npm run build && npx cap sync android
   ```
7. **Build debug APK:**
   ```bash
   cd android && ./gradlew assembleDebug
   ```
   Output: `android/app/build/outputs/apk/debug/app-debug.apk`
8. **Release APK:** create a keystore, sign with `./gradlew assembleRelease`. Keep the keystore backed up and **never commit it to git**.

**Requirements:** Node 20+, Android Studio (or Android SDK), a recent JDK.

## 4. UI/UX Design

**Style:** simple and calm. Lots of whitespace, one accent color (water blue), rounded cards, one clear action per screen.

### Screens (bottom navigation, 4 tabs)

- **Home:** large progress ring (today's intake vs goal), 3 quick-add buttons (150 ml, 250 ml, 500 ml), undo.
- **History:** weekly bar chart and streak counter.
- **Reminders:** on/off toggle, **Auto schedule** (default) or Manual, wake/sleep time, cup size, **notification type** (Sound / Buzz / Sound + Buzz / Silent), and a preview list of today's reminder times.
- **Settings:** theme (System / Light / Dark), daily goal, units (ml/oz), and a **Notifications** page with all notification options (section 5C).

## 5. Dark / Light Mode

- Three options: **System (default), Light, Dark**.
- Colors live in CSS variables; switch via a `data-theme` attribute on `<html>`.
- Save the choice in Preferences and apply it **before first paint** to avoid a white flash.
- Use `StatusBar.setStyle()` so status bar icons match the theme.
- Splash screen background matches the theme.
- Keep text contrast at WCAG AA or better in both modes.

## 5A. Auto Schedule (reminder times from water quantity)

The app builds the reminder times automatically from how much water the user needs to drink. No manual time picking.

### Inputs
- **Daily goal (ml):** user types it, or the app suggests one from body weight (about 35 ml per kg as a starting point, always editable).
- **Cup size (ml):** 150 / 250 / 500 or custom.
- **Wake time and sleep time:** the window in which reminders are allowed.

### Algorithm
1. `drinks = ceil(goal / cupSize)`
2. `window = sleepTime - wakeTime`
3. `interval = window / drinks`, rounded to the nearest 5 minutes.
4. If `interval` is under 30 minutes, show a hint: "Try a bigger cup" and cap at one reminder per 30 minutes.
5. Generate the time list from wake time forward.
6. Optional: front-load the day (slightly shorter gaps in the morning and afternoon, longer gap in the last 2 hours before sleep) so users are not drinking a lot right before bed.

**Example:** goal 2500 ml, cup 250 ml, 07:00 to 23:00 gives 10 drinks and a 96 minute window, which rounds to about every 95 minutes (07:00, 08:35, 10:10 and so on).

### Smart behavior
- **Adaptive:** if the user is behind pace, recalculate the remaining reminders across the remaining time. If they are ahead, space them out.
- **Auto-stop:** cancel the remaining reminders for today once the goal is reached.
- **Snooze:** "Remind me in 15 min" action.
- **Recompute** whenever the goal, cup size, wake time, or sleep time changes.
- **Reschedule daily** (and after device reboot) so reminders never silently stop.
- The Reminders screen shows the generated times as an editable list, so users can still remove or move a single reminder.

### Implementation notes
- Pure function `buildSchedule({ goal, cupSize, wake, sleep })` in `lib/schedule.ts`, easy to unit test.
- Schedule with `LocalNotifications.schedule()`, one notification per time slot, each with a stable ID so it can be cancelled or replaced.
- Store settings in Preferences.

## 5B. Notification Types (including Buzz)

Users pick how a reminder alerts them:

| Type | Behavior |
|---|---|
| **Sound** | Notification tone only |
| **Buzz** | Vibration only, no sound (good for work and meetings) |
| **Sound + Buzz** | Both |
| **Silent** | Notification appears in the shade with no sound or vibration |

### How it works on Android
- Android sets sound and vibration on the **notification channel**, and these cannot be changed after the channel is created. So create one channel per type:
  - `drinkup_sound`, `drinkup_buzz`, `drinkup_both`, `drinkup_silent`
  - Create them with `LocalNotifications.createChannel()` and use importance default or high (importance low or min can suppress buzzing).
- When the user changes the type, schedule new reminders on the matching channel (`channelId`) and cancel the old ones.
- Add the `VIBRATE` permission to `AndroidManifest.xml` (a normal permission, granted automatically).
- **Buzz strength:** the standard plugin channel supports vibration on/off. A custom vibration pattern (for example short-short-long) needs a small native Android addition, so treat it as a later upgrade.
- **In-app feedback:** use `@capacitor/haptics` for a tap when the user logs water, and a short buzz pattern when the goal is reached.
- **Test button:** a "Test notification" button in Reminders so the user can feel and hear the chosen type immediately.
- **Limits to explain in the UI:** the phone's Do Not Disturb mode, silent mode, and battery optimization can override or delay reminders. Add a short help tip that links to the system notification settings.

### Notification actions
- Buttons on the notification itself: **Drank 250 ml** (logs water instantly) and **Snooze 15 min**.
- Register with `LocalNotifications.registerActionTypes()` and handle `localNotificationActionPerformed`.

## 5C. Notification Options (Settings)

A dedicated **Notifications** page (Settings > Notifications, also reachable from the Reminders tab) with all the controls in one place:

| Option | Choices | Default |
|---|---|---|
| **Notifications** | On / Off (master switch) | On |
| **Alert type** | Sound / Buzz / Sound + Buzz / Silent | Sound + Buzz |
| **Notification sound** | A few built-in tones (soft water drop, chime, bell) with preview | Water drop |
| **Quiet hours** | Start and end time, no reminders in this window | Sleep time to wake time |
| **Snooze length** | 5 / 10 / 15 / 30 min | 15 min |
| **Message style** | Friendly ("Time for a sip!") / Simple ("Drink 250 ml") / Motivational | Friendly |
| **Show progress in notification** | Shows "1250 / 2500 ml" in the text | On |
| **Action buttons** | "Drank 250 ml" and "Snooze" on the notification | On |
| **Lock screen visibility** | Show / Hide content | Show |
| **Goal reached alert** | Celebration notification when the daily goal is complete | On |
| **Don't remind if goal reached** | Stops the remaining reminders for the day | On |
| **Weekend schedule** | Same as weekdays / Different wake and sleep time | Same |
| **Test notification** | Sends one now using the current settings | n/a |

### Behavior notes
- **Permission flow:** turning the master switch on requests `POST_NOTIFICATIONS` on Android 13+. If the user denies it, show a small banner with a button that opens the system notification settings, and keep the switch visually off.
- **Sound options** need extra channels, since Android fixes the sound at channel creation. Keep the sound list short (3 to 4) to limit the number of channels.
- **Quiet hours** are enforced by the schedule builder, so no reminder is ever generated inside that window.
- **Message style** only changes the text template, so it can change instantly without rescheduling channels.
- Every option saves immediately (no Save button) and the Reminders preview list updates live.
- Show a short helper line under each option in plain language, for example "Buzz uses vibration only, no sound."

## 6. UX and Performance Rules

### Speed
- Target under 1 second to a usable Home screen.
- Lazy-load History and Settings.
- Avoid heavy libraries; use SVG for the ring and charts.
- Animations 150 to 250 ms, only `transform` and `opacity`; respect `prefers-reduced-motion`.

### Feel
- Light haptic tap on every quick-add.
- Touch targets at least 48x48 dp.
- Primary actions in the thumb zone (bottom of screen).
- Handle the Android back button and safe-area insets (notch, gesture bar).
- Disable text selection and tap-highlight on UI chrome.
- Lock to portrait unless landscape is wanted.

### Clarity
- Empty states and a short 3-step onboarding (goal, reminders, permission).
- Ask for notification permission with a clear explanation, not on first launch.
- Feedback for every action (small toast with Undo).

### Reliability
- Fully offline.
- Reminders must survive device reboots; test on a real device with battery optimization on.
- Android 13+ needs the `POST_NOTIFICATIONS` permission; exact alarms may need extra handling.
